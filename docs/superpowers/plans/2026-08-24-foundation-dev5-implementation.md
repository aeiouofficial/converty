# FileConvert Foundation dev.5 Implementation Plan

> **For agentic workers:** Execute this tranche on `dev/v0.1.0-dev.5`. Use GitHub Actions as the qualified Windows/.NET 10.0.400 execution environment. Do not start B2 until the managed B0/B1 gate is genuinely green.

**Goal:** Close the dev.4 environment blockers by generating and reviewing deterministic NuGet lock files, executing the managed Release/xUnit/dependency-audit gates under .NET SDK 10.0.400, fixing evidence-backed defects test-first, and only then deciding whether B2 IPC may start.

**Architecture:** Runtime architecture remains unchanged until B0/B1 qualify. A temporary branch-only GitHub Actions workflow may generate lock files as an artifact without write credentials; reviewed lock files are then committed, the temporary workflow is removed, and the normal immutable/read-only CI becomes the authority.

**Tech Stack:** GitHub Actions, Windows Server 2025 runner, .NET SDK 10.0.400, C# 14/net10.0, Microsoft Testing Platform, xunit.v3.mtp-v2 4.0.0, PowerShell, Python static gates, CMake native topology smoke.

**Spec:** `docs/superpowers/specs/2026-08-24-foundation-design.md`

## Global constraints
- Work on `dev/v0.1.0-dev.5`; do not mutate `main` until the tranche is verified.
- SDK must be exactly `10.0.400`.
- Lock files must be generated by the real SDK, then reviewed and committed for all seven managed projects.
- No workflow may persist checkout credentials or receive repository write permissions solely to generate locks.
- Managed build/xUnit/dependency audit claims require actual GitHub Actions evidence.
- Do not weaken analyzers, warnings-as-errors, JSON strictness, schemas, dependency audit, or security boundaries to obtain green CI.
- Do not begin B2 if any B0/B1 managed gate remains red or dependency evidence is unresolved.

### Task 1 — Generate real NuGet lock files in an isolated CI workflow
- Add a branch-only temporary workflow pinned to immutable GitHub Action SHAs.
- Run `./build/bootstrap.ps1 -GenerateLockFiles` under SDK 10.0.400.
- Assert exactly seven `packages.lock.json` files exist.
- Publish only those lock files as an Actions artifact.
- Keep checkout credentials non-persistent and workflow permissions read-only.

### Task 2 — Review and commit generated locks
- Download the artifact and inspect all seven lock files.
- Confirm every project has lock format version 1 and expected direct dependency shape.
- Reject unexpected package sources or dependency families.
- Commit the exact generated lock files and remove the temporary generation workflow.

### Task 3 — Execute normal managed gates
- Trigger ordinary CI on the branch.
- Require locked restore, dependency vulnerability audit, Release build, Microsoft Testing Platform/xUnit tests, and native topology smoke to execute.
- Capture job/step/log evidence and fix only actual failures.

### Task 4 — Fix managed defects test-first
- For each compile/analyzer/test defect, add or preserve a failing test/gate demonstrating the defect before production changes where applicable.
- Make the minimum correction and rerun the affected job plus the complete managed/static gate.
- Preserve strict fail-closed behavior.

### Task 5 — Produce release dependency evidence
- Run release preflight after locks exist.
- Generate release-mode SPDX dependency SBOM from the committed lock graph.
- Record dependency-audit and SBOM evidence without claiming signing/runtime conversion.

### Task 6 — B2 decision gate
- If B0/B1 managed gates and dependency evidence are green, write the focused B2 Host/Bridge authenticated named-pipe IPC design/plan before implementation.
- Otherwise keep B2 blocked and document the exact remaining failure.

### Task 7 — Freeze dev.5 in GitHub
- Synchronize `VERSION`, README, CHANGELOG, status/backlog, handover, machine-readable evidence/state, and authority files to `0.1.0-dev.5` only after evidence is final.
- Run repository/static/provenance/vector/SBOM gates and inspect GitHub Actions status.
- Merge/fast-forward `main` only after the dev.5 branch is evidence-backed and clean.
- Provide a copy-paste dev.6 handover prompt referencing the GitHub repository/commit rather than requiring a ZIP.
